# 🚀 프로그래머스: 기능개발 (Python)

## 📌 문제 설명

프로그래머스 팀에서는 기능 개선 작업을 수행 중입니다. 각 기능은 진도가 100%일 때 서비스에 반영할 수 있습니다.

- 뒤에 있는 기능이 앞에 있는 기능보다 먼저 개발될 수 있지만, **뒤에 있는 기능은 앞에 있는 기능이 배포될 때 함께 배포**됩니다.
- 먼저 배포되어야 하는 순서대로 작업의 진도가 적힌 정수 배열 `progresses`와 개발 속도가 적힌 정수 배열 `speeds`가 주어질 때, 각 배포마다 몇 개의 기능이 배포되는지를 return 하도록 solution 함수를 완성하는 문제입니다.

---

## 💡 핵심 아이디어 & 접근법

1. **남은 일수 계산하기 (올림 처리)**
   - 각 기능이 100%가 되기까지 남은 일수를 계산합니다.
   - 파이썬의 정수 나눗셈(`//`)을 이용해 소수점 올림 효과를 내는 공식을 사용합니다.
   - **올림 공식:** `(100 - 현재진도 + 속도 - 1) // 속도`

2. **배포 그룹 묶기 (기준일 비교)**
   - 첫 번째 기능의 완료일을 기준일(`current_day`)로 잡습니다.
   - 뒤에 나오는 기능의 완료일이 기준일보다 **작거나 같다면 (`<=`)** 앞 기능과 함께 배포되므로 카운트를 증가시킵니다.
   - 기준일보다 **크다면 (`>`)** 앞선 기능들의 배포를 확정 짓고, 새로운 기준일과 카운트로 갱신합니다.

---

## ⏱️ 시간 복잡도

- **O(N)** (여기서 N은 작업의 개수, 즉 `progresses` 배열의 길이)
- 남은 일수 계산과 배포 그룹핑 과정 모두 리스트를 한 번씩만 순회하므로 매우 효율적입니다. (`N <= 100` 제한에서 여유롭게 통과)

---

## 💻 정답 코드

```python
def solution(progresses, speeds):
    # 1. 각 작업별로 완료까지 걸리는 일수 계산 (정수 나눗셈을 이용한 올림 처리)
    days = [(100 - p + s - 1) // s for p, s in zip(progresses, speeds)]

    answer = []
    current_day = days[0]  # 비교 기준이 되는 첫 번째 기능의 완료일
    count = 0              # 함께 배포될 기능의 개수

    for day in days:
        # 후배 기능이 기준일보다 같거나 빨리 끝나면 함께 배포 가능
        if day <= current_day:
            count += 1
        else:
            # 기준일보다 늦게 끝나면 이전까지의 그룹을 배포 확정
            answer.append(count)
            current_day = day  # 새로운 기준일 갱신
            count = 1          # 새 그룹 카운트 시작

    # 마지막에 남아있는 그룹의 개수도 잊지 않고 추가
    answer.append(count)

    return answer
```
